# 电子账单入账（一期）

把美菜这类**电子单截图**交给视觉大模型抽出明细，再按行做品名映射和单位换算，写入物料明细表。这是会计入账，不是 OCR 流水线。

一期只做这件事：

1. 视觉模型按行抽出品名、数量、单位、金额、行类别（蔬菜 / 肉类）。
2. 用品名目录、别名和可选的模型建议，把电子单上的名字对到表内品名。表里没有的（比如可乐）跳过，不写。
3. 落表前把数量换算成该品名在物料表上的单位。没有对应规则就整行跳过，不猜。
4. 蔬菜写入「日物料采购」，肉类写入「肉类采购」。类别按行判断。
5. 「确认」只锁定人工复核。「同步到物料明细」才把**全部已确认单据**按日期 + 物料单元格重写合计。

## 一期不做

- 不接手写单，不走传统 OCR。
- 不写「员工餐」表，也不写「公司物料采购」「综合表」。
- 不根据整张单的一个类别把所有行刷成蔬菜或肉类。
- 确认按钮不改物料明细表。
- 不同步时去读单元格旧值再累加。重复同步写的是同一批已确认单据的合计。

## 配置密钥

复制 `.env.example` 为 `.env`，二选一填写：

```bash
HUNYUAN_API_KEY=你的访问令牌
# 或
MOLLI_ARK_API_KEY=你的访问令牌
```

程序先读 `HUNYUAN_API_KEY`，为空再读 `MOLLI_ARK_API_KEY`。密钥只来自环境变量，不要写进仓库。

模型名和接口在 `config/models.json`，也可以用环境变量盖过：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `VISION_MODEL` | 视觉抽行和品名映射用的模型 | `Qwen3.5-Flash` |
| `VISION_API_BASE` | OpenAI 兼容接口根路径 | `https://ai.gitee.com/v1` |
| `MAP_CONFIDENCE` | 模型映射自动采纳的最低置信度 | `0.8` |

提示词在 `prompts/extract_lines.md` 和 `prompts/map_names.md`，改完即生效，不用改代码。

## 安装和启动

在仓库根目录：

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn webapp.app:app --host 127.0.0.1 --port 8000
```

也可以运行 `scripts/run.sh` 或 `scripts/run.ps1`。浏览器打开 http://127.0.0.1:8000 。

自测：

```bash
python -m pytest
```

## 页面怎么用

1. 填写电子单截图目录和物料明细 `.xlsx`，点「扫描目录」。
2. 点「识别当前」或「识别未确认」。没有密钥时会直接失败，不会假造一行明细。
3. 按行改物料品名、数量、单位、金额和行类别。预览会写它将进入哪张表；对不上的行标红。
4. 「确认（不写表）」锁定这张单。要改，先「取消确认」。
5. 「同步到物料明细」处理**所有已确认单据**。结果里能看到写入了什么、跳过了什么。

同日多张单里的同一物料会先加总，再写入那个日期列。已经确认、后来又取消的数量，下次同步会从合计里拿掉。

## 物料表怎么读

「日物料采购」和「肉类采购」使用同一套矩阵：

- D 列品名，E 列单位，B 列物料代码。
- 表头行同时有「品名」和 Excel 日期序列号。日期下面一行是「数量 / 单价 / 金额」。
- 数量写在日期那一列，金额写在其后两列。单价和「合计」列不动。
- 没有该日期列，或金额列表头不是「金额」，这一行跳过，不新开列。

列位置在 `config/sheet_layout.json`。

## 品名和单位

- 别名：`config/aliases.json`。确认时如果票面名和表内名不同，会追加到 `webapp/aliases.local.json`（不提交）。本地别名优先。
- 示例别名是「无敌美味小小葱 → 小葱」。表里的品名必须真实存在；如果表上写的是「香葱」，请改 `name`，否则这行会跳过。
- 换算：`config/unit_conversions.json`。示例是鸡蛋「板 → 个」，系数 30，并且**只适用于品名鸡蛋**。煲汤袋、香葱不会套用。换的是数量，金额仍是票面金额，不乘系数。
- 票面单位和表内单位相同（包括「个 / 個」这种写法）时不换算。当前若表里鸡蛋的单位本来就是「板」，2 板仍写入 2，不会乘 30。
- `applies_to` 为空的规则会被忽略，避免一条单位规则套到所有货。

## 目录

```
config/          模型、表布局、别名、换算
prompts/         视觉抽行和品名映射提示词
foodmix/         映射、换算、分表、同步
webapp/app.py    FastAPI
webapp/static/   复核页
tests/           换算、别名、跳过、按行分表、幂等同步
```

运行时文件 `webapp/settings.json`、`webapp/state.json`、`webapp/aliases.local.json` 不入库。同步前会在物料表旁边生成 `.bak_时间戳` 备份。

## 已知缺口

- 仓库不带真实美菜截图，也没有无密钥时的假识别。视觉结果要靠人工复核。
- 换算系数 30 是示例，落地前按实际规格改配置。
- 页面不能代替你检查物料表里是否已有这一天的手工数。本程序第一次写某个日期格时，会用已确认合计盖掉格里的旧数，而不是相加。同步前看备份。
- 本程序上次写过、这次合计里不再出现的格子会被清空。没写过的格子保持原样。
- 金额列如果原来是公式，同步后变成数值。单价列不改。
- 日期列不存在时不会自动加列。漏识别的行可以「补一行」，但没有票面原名。
